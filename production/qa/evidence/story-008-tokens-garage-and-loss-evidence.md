## Measured engine facts the code comments point at ("Story 008's engine preflight")

Logs in `measurements/preflight-engine-logs/`, results in `measurements/engine-preflight-result.json`, the slice reports in `measurements/slice-reports/`. Godot 4.7.2, Jolt, headless `--fixed-fps 60` and, where said, windowed.

1. **Order inside one physics frame.** `PlayerDriveInput` ×2, `PlayerMatchInput` ×2, `PlayerChoiceInput` ×2 (priority −1, tree order); then the Map's nodes, the Units, `PlayerFireInput` ×2, the Shots, the `MatchController` and `RoundRestartInput` (priority 0, tree order); last the Weapons (+1). A Shot fired in frame N first ticks in N + 1 (`pf_order.log`, `pf_order_map.log`). The loss check's guarantee rests on default priority 0 plus tree position, not on a declared priority; `loss` T20 asserts it.
2. **Every real destruction source lands before the controller's tick of the same frame:** Tab, Enter, a Shot kill and a Gyrocopter's Fuel crash (`pf_q2.log`); Tab and Enter pressed in one step destroy both Units in one frame; a Self-destruct plus a lethal Shot in one frame is one double loss. A source later in the frame (priority +5) or in the idle phase is decided one frame later.
3. **The pause is mid-frame.** Once the controller sets `paused = true` at the end of the loss tick, no pausable node later in the frame ticks; a `process_mode` ALWAYS node still does and a destruction from it still takes its Token and is announced, but cannot change the result (`pf_q4.log`).
4. **At a Round's end** every `RespawnCountdown` and `UnitChoice` hides and the Round-over screen shows in both views; nothing is left over its panel (`pf_q5.log`, `measurements/preflight-pictures/`). A standing choice is cleared by the restart, which costs no Token; frozen Shots are freed by `SplitScreen._free_shots`, a `round_started` listener (`pf_q7.log`). `Unit.destroy()` on a Unit that is not alive is silent; `leave_play()` emits no `destroyed` (`pf_q6.log`).
5. **A key event** the harness injects at the start of a step or in the idle phase after it is first seen by the input nodes' edge reads in the next step; a key pulsed in two consecutive steps loses the first edge (S2b); a Shot from a Motorbike at 10 m kills in frame N + 8 of the Shot node's frame (`LETHAL_LEAD`).
6. **Typed dictionaries.** A literal assigned to a `Dictionary[StringName, int]` property works; an untyped `Dictionary` variable assigned to it is a runtime script error; `Resource.duplicate()` SHARES the `counts` dictionary with the cached `.tres` (writing the copy changed the shipped stock), `duplicate_deep()` and `TokenStock.new()` do not (`typed_dict.log`); `MatchRules.duplicate()` shares `unit_types` and `DamageMatrix.duplicate()` shares its multipliers (S1a). `Array[Dictionary[StringName, int]]` is a parse error ("Nested typed collections are not supported").
7. **GDScript reads a negative index from the end** of an array (`names[-1]` returned the last name), so no code indexes `unit_types()` with a possible −1; `carrier_type_index()` is −1 before a successful `begin()`.
8. **A Label's default font colour is white** (1, 1, 1, 1), also after adding and removing an override, so `remove_theme_color_override()` falls back to the same white the scene stores; the panel still sets both colours explicitly on every refresh and `token_choice` puts a red-text Theme on the panel to make that contract observable. (The design block's "grey" was wrong.)
9. **A constant array of typed arrays indexed with a literal** is read as `Array[int]` and refused at parse time (the reason `token_kit.gd` builds key lists with a function). A `Logger` subclass added with `OS.add_logger` counts `push_error` (error type 0) and `push_warning` (1) apart and cannot see anything logged before it is installed (`begin()` inside `SplitScreen._ready()`). The runner's watchdog is a SceneTree timer: it cannot fire when a `_physics_process` never returns, so an unbounded cursor search is ended only by the external timeout (S3b).

## Notes, gaps and decisions recorded here

1. **No guard in the spawn path (a deviation from the story's implementation note).** The note says the one spawn path refuses a type with 0 Tokens. A Player with no Unit in play cannot lose a Token and `choose()` refuses an empty type, so such a branch is unreachable, untestable, and could only clear the choice without a signal (the panel would keep showing "X ready"). `MatchController.choose()` is the single guard of AC-3; `token_choice` T13 and `loss` T18 prove it through every key and by direct calls. `garage_queue.gd` has only doc fixes.
2. **Exactly one Unit type may carry the Flag.** `begin()` refuses none or several (the rules speak of "the last Motorbike"). With two carrier types the HUD would show one number and the loss read another. The error names the types.
3. **`begin()` refuses more than a missing Motorbike Token:** an unknown stock key (a typo would silently make a type unavailable all Round), an empty or duplicate type id, a negative count, no stock. One error each, naming the problem, before anything changes (`tokens_data` T03, T04).
4. **The ledger is keyed by type id, not by position.** `destruction.gd` swaps `controller.rules` for a copy at runtime; by id the charge and the choice stay right whatever the order or length of the live list (`tokens_data` T35, which now keeps a reversed copy through a loss, an R and a second Round).
5. **The count the HUD shows includes the Unit in play** (5 while the first Motorbike drives, 4 after it is destroyed, 1 on the last one). Recorded in `design/rules.md`.
6. **A Self-destruct of the last Motorbike is a forfeit.** It costs a Token like any destruction, so a Player who spends the last Motorbike on it loses the Round. Recorded in `design/rules.md`.
7. **`R` pressed in the loss tick itself restarts the Round inside that tick** (`RoundRestartInput` runs right after the controller and is `process_mode` ALWAYS): the Round-over screen is never drawn. The same already held for a delivery; a delay on R is outside the story.
8. **The winner can be a Player whose own Unit is destroyed at that moment** (it lost a non-last Token earlier or on the loss tick): "Player 2 wins!" over a HUD that reads HP 0 / 40. A consequence of deciding by Tokens.
9. **A destruction while the Round is over** (impossible in the game: only an ALWAYS-mode node could cause one) takes its Token and is announced but cannot change the result; `loss` T21 runs that branch from the scenario.
10. **Scenario sizes.** The set grew from 9,876 lines in 45 scripts to 13,661 in 58 (the runner from 698 to 780): `tokens` 328 + `token_kit` 338, `tokens_data` 469 + kit 235, `token_choice` 462 + kit 146, `loss` 335 + kit 267, `token_ui` 319 + kit 160, `token_layout` 250, `tokens_showcase` 280 + kit 194. Recorded in TD-006; the orchestrator accepted them rather than trim evidence.

## Notes for the author

- **The choice cursor after a restart.** It is kept across a restart as Story 005 decided ("a Player who keeps choosing the same type confirms with one press"), and since this story it also snaps off a type with no Tokens left. So after a Round lost by the last Motorbike the loser's cursor starts the next Round on the Buggy (09, 14) and a bare fire key right after R picks a Buggy, not a Motorbike.
