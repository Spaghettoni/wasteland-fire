**1. Strokes are lost in any frame with two or more physics ticks** (tyre_tracks.gd:151-154; tyre_track_painter.gd:57-58)
- **Scenario:**
  - Deferred calls flush after each physics step, so `_draw()` runs once per tick, and every redraw starts with `canvas_item_clear`.
  - The SubViewport renders once per frame, so tick 1's quads are recorded, dropped from the list, then wiped by tick 2's redraw.
  - At 30 fps every second stroke never reaches the map, so the tracks come out dashed. `--fixed-fps 60` cannot show this.
  - This comes from my memory of the 4.x main loop, not from source. Confirm with a windowed `--fixed-fps 30` readback.
- **Fix:** keep `painter.add` in the tick. Move `queue_redraw()` and `UPDATE_ONCE` into `_process`, guarded by `painter.waiting() > 0`.

**2. `_exit_tree` zeroes a process-wide global unconditionally, and only `_ready` sets it back** (tyre_tracks.gd:137-142)
- **Scenario:**
  - If a replacement Map enters before the old one leaves (add the new scene, then free the old), the old exit publishes strength 0 after the new `_ready` published 1.
  - Match two then has no tracks and no error.
  - A node removed and re-added also stays off.
  - I did not read the scene-swap code.
- **Fix:** re-publish on `NOTIFICATION_ENTER_TREE` when `_usable`. In `_exit_tree`, reset only if `RenderingServer.global_shader_parameter_get(MAP_GLOBAL) == track_viewport.get_texture()`.

**3. Old marks show at full strength for one frame after a restart** (tyre_tracks.gd:165-174; spatial_env_ground.gdshader:184-185). This needs a windowed check.
- **Scenario:**
  - `clear()` publishes clock 0 at once, but the map clears only when the TrackMap next renders.

- **Fix:** publish LOOK with w = 0 in `clear()`. Restore w = 1 in the next `_physics_process`.

- **Fix:** set `process_physics_priority = -100` on TyreTracks.
